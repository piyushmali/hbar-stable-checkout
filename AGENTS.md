# Agent instructions

Briefing for coding agents (Cursor, Claude Code, Codex) working in a copy of the **hbar-stable-checkout**
Scaffold-HBAR template. Claude Code loads it through `CLAUDE.md`. Humans: start with [README.md](README.md).

The app: a customer pays an invoice in HBAR, `StableCheckout` swaps it to USDC on SaucerSwap V1 in the same
transaction with a Chainlink HBAR/USD floor, pays the merchant through HTS, and a server route writes an HCS receipt
after verifying the payment on the mirror node. Hardhat + Next.js App Router, Yarn workspaces, Hedera testnet first.

## Invariants: never break these

1. **The oracle floor.** `pay` must revert unless the swap returns at least the Chainlink value of `msg.value` minus
   the merchant's slippage (`maxSlippageBps <= 300`). Never compute the floor from the pool's own quote, never derive
   it from the invoice amount instead of `msg.value`, and keep the completeness, sign and staleness checks in
   `latestPrice()`.
2. **The association checks.** The constructor must keep `associateToken(address(this), usdc)` and revert on any
   response other than 22 or 194. Payouts must go through `transferToken` with its response code checked
   (184 → `PayoutNotAssociated`). The pay page must keep blocking payment when the payout cannot receive USDC.
3. **No secrets in the client bundle.** `HEDERA_OPERATOR_KEY` and `DEPLOYER_PRIVATE_KEY` are read only by server
   code and scripts. Never prefix them with `NEXT_PUBLIC_`, never import `services/hedera/receipts.ts` from a client
   component, never commit a `.env` file (only `.env.example`).
4. **The receipt route stays idempotent and verified.** Receipt fields come only from the mirror node's contract
   result for the hash (status `SUCCESS`, our `contract_id`, an `InvoicePaid` log from it), never from the request
   body. Keep the existence check before `TopicMessageSubmitTransaction`.
5. **Units.** Contract HBAR amounts are tinybars. Transaction `value` from the frontend is
   `tinybars * WEIBARS_PER_TINYBAR`. Do not use `parseEther` on contract-side amounts.
6. **Every page returns 200 before anything is deployed or configured.** Gate on `useDeployedContractInfo` and
   `/api/health`, show `DeployFirst` or a configuration notice instead of throwing.

## Commands, in order

```bash

yarn next:build                   # production build with type checks
yarn typecheck                    # hardhat compile + tsc for both packages
yarn fork:test                    # optional: read-only checks against live mainnet (network access)

# Hedera testnet (needs packages/hardhat/.env)
yarn hardhat:deploy --network hederaTestnet
yarn hardhat:create-topic         # then put HCS_TOPIC_ID in packages/nextjs/.env.local
yarn hardhat:demo-pay             # real $0.10 payment; prints the receipt curl
yarn next:dev                     # http://localhost:3000
```

CI runs exactly `yarn install && yarn lint && yarn hardhat:test && yarn next:build` on a fresh scaffold, then boots the
app and expects 200 from `/`, `/merchant`, `/pay/<id>`, `/receipts` and `/api/health`. Run the same before you push.

### What the mocks simulate

The hermetic tests install `MockHTS` at `0x167` with `hardhat_setCode`. It associates accounts (returning 194 when
already associated, or a forced code to simulate failures), and `transferToken` refuses unassociated senders or
recipients with 184, like HTS. `MockRouter` pays a fixed USDC-per-HBAR rate out of its own balance through that HTS
mock, so the contract must be associated to receive the swap; `setUsdcPerHbar` simulates a thin or skewed pool.
`MockAggregator` publishes any round (stale, zero, negative, incomplete). Tests send tinybar amounts as `value`,
because Hardhat has no relay doing the weibar conversion.

## Recipes

### Add a new settlement token

1. `packages/hardhat/config/hedera-testnet.ts` and `hedera-mainnet.ts`: set `usdcToken`, `usdcTokenId`, with a source
   comment. The token needs a WHBAR pool on the SaucerSwap V1 factory (`getPair`) and 6 decimals.
2. `packages/hardhat/contracts/StableCheckout.sol`: only if the token is not 6 decimals, convert `usdAmount6` in
   `_quoteUsdc` and `quoteTinybars` and relax the constructor's decimals check.
3. `packages/hardhat/test/StableCheckout.test.ts`: cover the new decimals if you changed them.
4. Redeploy (`yarn hardhat:deploy --network hederaTestnet`); the UI reads the token from `usdc()`.
5. `README.md` integration table and `docs/oracle-floor.md` units table.

### Add a fee recipient

1. `StableCheckout.sol`: add an immutable `feeRecipient` and `feeBps` (bounded), split `usdcOut` in `_sendUsdc` into
   two `transferToken` calls with response codes checked, add the fee to `InvoicePaid`.
2. `deploy/00_deploy_stable_checkout.ts`: pass the new constructor arguments.
3. `test/StableCheckout.test.ts`: balances of payout and fee recipient, and an unassociated fee recipient.
4. `packages/nextjs/utils/checkout.ts`: add the fee to `INVOICE_PAID_EVENT` and `receiptSchema` as `v: 2`.
5. `services/hedera/receipts.ts`: map the new field; keep accepting `v: 1` when reading old messages.
6. `app/pay/[invoiceId]/page.tsx` and `app/receipts/page.tsx`: show the fee.

### Swap the oracle provider (Pyth or Supra)

1. `contracts/interfaces/`: add the provider's interface.
2. `StableCheckout.sol`: rewrite `latestPrice()` only, returning the price scaled to the feed decimals that
   `priceScale` assumes, and keep the sign and staleness checks. Pyth is pull-based: `pay` must receive the Hermes
   update bytes and pay `updatePriceFeeds`, so `pay` gains a parameter and the value split changes. Supra's
   `getSvalue` timestamps are in milliseconds.
3. `contracts/mocks/MockAggregator.sol` or a new mock, and the oracle tests.
4. `config/hedera-*.ts`: the feed address with its source. `deploy/00_deploy_stable_checkout.ts`: constructor args.
5. Skills: `pyth-price-feeds`, `supra-push-oracle` (see below).

## Hedera gotchas

- **Decimals.** HBAR is 8 decimals in the EVM and HAPI, 18 in a JSON-RPC transaction's `value` (weibars). USDC and
  invoice amounts are 6. Chainlink's Hedera HBAR/USD feed is 8.
- **HBAR wording.** Write "HBAR" uppercase and singular ("250 HBAR"), "tinybars" lowercase and plural, and network
  names in lowercase ("Hedera testnet").
- **Association.** An account must be associated with an HTS token before it can receive it, unless it has free
  automatic association slots (`max_automatic_token_associations` −1 or above its count). EVM-alias accounts default to
  −1. HIP-719: an EOA can call `associate()` on the token address.
- **ECDSA keys only.** The relay and wallets sign with secp256k1. ED25519 accounts have no EVM address. A new EVM
  address that receives HBAR becomes a hollow account; its first signed transaction completes it.
- **Gas.** Hedera bills at least 80% of the gas limit and the relay's estimate is reliable here, so size limits as
  estimate × 1.2 (`withGasHeadroom`). A payment is ~225k gas, ~930k when HTS auto-associates USDC on the first payout.
- **Mirror node lag.** Consensus to mirror node is a few seconds. Poll with backoff; the pay page retries the
  receipt POST after 1, 2, 4, 8 and 16 seconds on `404 not_indexed`.
- **Long-zero addresses.** `0.0.N` is `0x` + N in 40 hex digits. SaucerSwap's router and tokens use these; contracts
  you deploy get a CREATE address as well. Match mirror node logs by `contract_id`, not by address string.

## Frontend conventions

- Scaffold hooks live in `packages/nextjs/hooks/scaffold-hbar`: `useScaffoldReadContract`,
  `useScaffoldWriteContract`, `useDeployedContractInfo`, `useTransactor` (not the `useScaffoldContractRead` spelling).
- Imports use the `~~` alias. Pages that use hooks start with `"use client"`.
- Use DaisyUI classes (`btn`, `card`, `alert`, `badge`). DaisyUI 5 alerts are grids: wrap multi-line content in one
  `div`.
- Prefer `type` over `interface`. Comments explain why, not what.
